# 22 张能力卡

开发入口 `/?live=cards`，隔离联调入口 `/?live=cards&training=1`，正式部署见 [部署说明](../deploy/README.md)。服务端管理库存、证据权限、计时、审核和持久账本。未指定扣分默认 5 分，“加分”默认 5 分，一般限制完成不额外奖励；未指定时限取 10–20 分钟。后台修改规则须写理由，已使用卡保存使用时的规则快照。

第 22 张英语标准答案仅以摘要用于自动校验，不在玩家卡面/接口公开；忽略大小写、空格及中英文标点。中文整句经工作人员审核语义，保留原服务器接收顺序。有待审核中文答案时禁止结算。采用每队第一条判定正确的服务器接收顺序，不能用客户端时间改变名次；到期未正确提交的队伍并列最慢，各 −5。只有一队正确时，该队只获得最快奖励。

## 接收、证据与审核

第 3、8 张立即生效，其他卡先由工作人员确认；确认前锁定卡牌，取消/打回归还。第 5 张确认即转分。其他卡目标接收后才开始计时，全队竞赛所有目标接收后共同开始。未接收不会静默开始；工作人员可现场沟通或填写理由终止。

持续行为卡不能提前确认成功，可在发现违规后确认失败。任务型卡到期后，需有期间提交的证据，或工作人员明确勾选“已现场确认在规定时间内完成”。截止后禁止新证据，保留旧证据供审核。计时按比赛累计时间，暂停冻结。

照片、笑容、动作、朗诵、肢体接触、曲目难度、饮品、语言内容和圆周率正确位数均由工作人员现场核实，系统不冒充自动识别。可提交说明、图片或 MP4/WebM 短视频，单文件 8 MB；视频仅检查容器头、保存原件，解码和内容真实性须播放验证。第 19 张触碰确认须有其他队伍的图片/视频证据。

第 2 张以接收时最新 GPS 为锚点，容差取25米与两次精度之和的较大值；只提醒，不因 GPS 漂移自动扣分。第 14 张选择十分钟前时刻之前最近的采样点，距目标时刻不得超过两分钟；历史不足时拒绝使用且不消耗。回返点仅目标与定位工作人员可见。

第 20 张在开赛前保存本人昵称，开赛后昵称锁定，服务端随机目标一次固定，提交必须选三位本队注册成员，保存昵称快照。拼词可行性由工作人员确认。第 21 张由工作人员记录确认的小数位数，现场另验三人协作与30秒时限。

第 15 张原项目没有独立任务分配表，采用“双方所选待做任务交换为下一任务”：目标选另一队和两个任务编号，双方下一次普通任务必须完成交换后任务，审核通过解除。只能交换未归属、无待审核、无已有分配的任务，历史分数和照片不交换。

完成本区五项计分任务后，从启用的22张卡随机发一张，同一区域不重复发放。所有积分追加账本，相同幂等键重试返回原结果，不同键不能重复用卡或结算。事务同时保存审核、库存、证据和分数。玩家仅可看本队证据，工作人员按审核权限访问；追逐位置仅限有效期公开，完整轨迹始终按定位权限控制。

## 测试

```sh
npm test
npm run test:backend
npm run test:abilities:local
npm run build
```

联调界面可用“推进30秒/5分钟/15分钟”控制模拟时钟。第22张隔离测试使用每次随机生成的独立测试答案，只发给持有测试密钥的创建者，正式答案不进入前端测试脚本。测试页“一键测试 22 张能力卡”和命令行共用同一脚本，建立22个独立三队三人的临时赛局，通过真实 HTTP 验证权限、库存、确认、接收、积分、截止与访问隔离，并尝试清理。报告：忽略的 `artifacts/ability-test-report.json`。另有接口回归测试暂停、重复结算、历史位置、位移提醒、半分奖励、交换、中文审核及重启恢复。

本机结果：22项通过、0项失败、1项现场/异地待验收。本机数据库为 PGlite，不能声称异地 PostgreSQL 已部署。实机 GPS、视频播放、现场行为、公网延迟与服务器恢复需部署后再验收。
